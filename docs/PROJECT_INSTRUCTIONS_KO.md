# NATURE VIDEO STUDIO V2 — 프로젝트 지침 (Codex / Claude Code 공통)
버전: 2.0.0-plan | 2026-11-05 | 저장소: https://github.com/1976haru/newvideo

## 1. 제품 목표
한국어 Windows 데스크톱 프로그램. 무료로 재사용 가능한 호수·산·숲·바다·폭포·눈·벚꽃·일출·노을·산책 고화질 영상을 검색, 확인, 미리보기, 선택 다운로드, 분류해 15곡 플레이리스트 배경 제작에 활용한다. 최우선은 **3분 이상 이어지는 원본 풍경 영상**이며, 대안은 여러 개의 짧은 클립을 편집한 자연스러운 시퀀스다. 소스 권리를 훼손하지 않고 사용한다.

## 2. 고정 사용자 요구
- 한국어 GUI, Windows 10/11 x64, 원클릭 실행/설치형 EXE, 비전문가도 사용 가능.
- 저장 위치 기본 D:\\NatureVideoStudio, 드라이브 부재 시 안전한 사용자 폴더로 대체. 기존 다운로드·API 키·DB 자동 삭제 금지.
- 기본 검색 의도: 자연풍경 / 실사 / 가로 16:9 / 4K 우선 / 원본 180초 이상 우선.
- **원본 긴 영상**과 **짧은 클립 조립**은 완전히 별도 모드 및 표시.
- 고정 카메라, 걷기, 드론, 타임랩스, 수면 움직임, 계절, 장소, 시간대 태그를 지원하되 미확인 시 미확인으로 표기.
- 결과에 실제 썸네일, 제목/제작자, 원본 길이, 실제 해상도, 가로/세로, 출처, 라이선스/귀속 상태, 다운로드 가능 여부를 표시.
- 짧은 영상은 자연스러운 3~30분 시퀀스로 만들 수 있어야 한다. 속도 과도 변경, 같은 장면의 눈에 띄는 반복, 무허가 콘텐츠 합성 금지.
- 15곡 WAV/MP3 + 12초짜리 '01. 곡명' SRT는 후속 버전으로 통합.
- 4K 없는 영상을 AI 업스케일해 실제 촬영 4K라고 표시하지 않는다.
- API 키는 Windows 보안 저장소, 저장 영상과 메타데이터는 로컬 유지.
- 원본 클립에 타인의 음악/인물/상표/저작물이 있으면 별도 위험 경고.

## 3. 소스 정책
- Pexels: 짧은 B-roll 전용 우선. 공식 업로드 기준 영상 최대 120초(2026-10-04 확인). 180초 이상 원본을 기대하지 않는다. 공식 /v1/videos/search API, 페이지 출처 링크/제작자 크레딧.
- Pixabay: 짧은 영상 수집; API 결과의 실제 duration/large rendition 확인, 180초 이상인 경우만 긴 영상 탭에 진입. 필터가 없으면 로컬 평가.
- Wikimedia Commons: 장편 후보 검색 공식 API; FILE별 실제 duration/height/width/라이선스/저작자/출처 확인.
- Internet Archive: 긴 후보 검색; title/subject만 믿지 말고 시각 적합성과 파일별 길이·화질·권리 메타데이터를 확인. licenseurl 미확인·NC·ND는 자동 다운로드 금지.
- 사용자가 직접 촬영한 로컬 영상: 길이 무관 지원, 생성 경로 구분.
- 무단 유튜브/Vimeo/유료 스톡 대량 다운로드, API 제한 회피, 쿠키 우회 및 저작권 세탁 금지. 신규 소스는 공식 문서/허용범위를 확인한 후 플러그인 추가.

## 4. 검색/결과 UX
검색어는 한국어/영어/일본어 지원하며 영문 동의어 확장 가능하나 '호수'에서 회의 영상으로 변질되면 안 된다.
- 탭 A '3분 이상 원본': duration >=180s, 원본 길이 검증 여부, 4K/FHD 상태 표기. 0건이면 '없음' 및 이유 안내. 짧은 영상 자동 혼합 금지.
- 탭 B '짧은 영상 조합': 5~120초 클립 별도 탐색, 3/10/20/30/60분 결과물 시간 설정.
- 원본 4K 엄격 모드 / 4K 우선(없으면 FHD 별도 표시) / FHD 모드.
- 정렬: 실제 길이, 적합도, 4K, 저작권 상태, 산책/고정 여부. 정확한 선택 근거 표시.
- 촬영자 중복, source ID, 해시, 후보 이미지 유사도, 같은 장면 반복 경고.
- 버튼은 동작 보장. 로딩/실패/성공/중단/재시도 모두 상태에 반영.

## 5. 미리보기 필수 품질
1차: 공식 API 포스터 이미지 다운로드, 로컬 캐시. HTTP 코드, redirect, TLS, 유효한 이미지 MIME, 크기 제한, 시간초과를 체크한다.
2차: 원본/허용된 프리뷰 영상의 QMediaPlayer 동영상 재생(플레이·정지·시크·음소거) 및 로컬 파일 재생.
3차: 실패 시 정확한 원인·재시도·원본 페이지 열기. 이미지 오류를 동영상 재생 실패와 혼동하지 않는다.
모든 네트워크 처리는 UI 스레드를 막지 않는다. 여러 결과를 연속 클릭해도 이전 응답이 새로운 결과를 덮어쓰지 않는다.
원격 재생에 제한이 있으면 포스터만 + 원본 페이지로 표시한다.

## 6. 권리/출처 증빙
각 클립마다 provider/source_id/source_url/file_url(or sanitized version)/creator/license_url/license_text/license_version/attribution/checked_at/approval_status/actual_fps/duration/width/height/sha256 저장.
권리 상태: GENERAL_REVIEW, ATTRIBUTION_REQUIRED_REVIEW, BLOCKED, USER_VERIFIED. 기계가 일반 이용 약관을 확인해도 자동으로 개별 권리 문제 해결이라 선언하지 않는다.
NC(비영리), ND(변경불가), 불명확 라이선스는 상업적 영상 제작에서 기본 차단. BY-SA 등 추가 조건은 수동 검토.
영상 다운로드는 사용자가 고른 것만, 해당 사이트의 약관과 API 제한 안에서 수행한다.

## 7. 검색/다운로드 안정성
사이트별 어댑터 격리, 요청 제한 존중, 429 백오프·Retry-After, 24시간 결과 캐시 권장(정확한 공급자 약관 우선), 중복 방지, range/resume 지원 확인, 임시파일 + 원자적 rename, 파일 해시, 최소 잔여 공간, 다운로드 중단·재개. 범용 URL fetch를 사용하지 말고 도메인 allowlist와 redirect 검증. 바이러스/실행 파일 등 거부.

## 8. 영상 조합
FFmpeg/ffprobe로 실제 코덱·fps·길이·해상도 확인. 다른 포맷을 안전하게 정규화한 뒤 연결한다.
- 우선 한 장면 최소 20~60초 체류, 고정 70% / 산책 30% 기본 프리셋.
- 크로스페이드 0.5~1.5초, 반복 최소화, 자연스럽지 않은 reverse/과도한 속도 변경 금지.
- 컴포지션 완료 후 영상 길이·오디오 동기화·black frame·중복 검출, 실행 가능한 MP4 검사.
- 15곡 + SRT(연번 + 제목, 시작 후 정확히 12초) 후속 확장.
- 방송용 재사용 저작권/YouTube 수익화 승인은 별도 검토.

## 9. 개발원칙과 운영
- GitHub main은 항상 작동 가능. feature 브랜치→초안 PR→Windows CI→수동 스모크→머지.
- Codex/Claude Code는 한 번에 하나의 수용 기준을 완결하고, 증거 없는 PASS·100% 주장 금지.
- 설치 스크립트 .cmd: ASCII 명령 + CRLF. 한글 경로와 공백·괄호 포함 경로 테스트.
- Windows GUI와 다운로드를 실제 테스트하지 않았다면 완료 아님. 의존성 설치·실행·배포·업데이트 시 데이터 보존.
- 테스트: 유닛+모의 API+보안+네트워크 오류+렌더링+윈도우 EXE 구동+실제 승인된 무료 샘플 1건.
- 로그에 API 키·서명된 URL·개인정보 노출 금지.
- 오픈소스는 라이선스 검토와 NOTICE 후 사용. 참고한 설계와 복사한 코드 구분.

## 10. 매 응답 필수 보고
전체 진행률(기준 정의), 지금 완료한 일, 검증 명령 및 PASS/FAIL/SKIP, 브랜치·커밋 SHA, 미완료/차단 사항, 다음 3개 과제. 부분 성공을 전체 완료로 포장하지 않는다.

## 12. 사용자 확정 운영 방식 — 단일 로컬 V2 설치본에서 순차 실사용 점검 (2026-11-07)

**사용자 요청:** 체크리스트마다 새로운 프로그램 설치 폴더를 생성하지 않는다. **현재 사용자 PC에 이미 설치된 V2 시험판의 동일 실행 위치**를 사용하여, 기능 구현 → CI → **같은 V2 설치본에 안전한 업데이트** → 직접 GUI 실행·테스트 → 오류 발생 시 수정·재실행 → 문제없을 때 다음 체크리스트로 진행한다. 이 운영 변경으로 새로운 체크리스트 항목을 늘리지 않는다.

- 기존 확인된 V2 시험 설치 경로는 `D:\NVS_V2_Trial_App\C011_Titlebar_10206483`. **폴더 이름에 C011이 포함되어도 재설치 경로를 계속 증식시키지 않는다.** 향후 이 동일 V2 실행 위치 또는 안전한 고정된 V2 바로가기만을 사용한다. 재설치 시 C011 디렉터리를 무조건 삭제/초기화하지 않는다.
- C011 기존 V2 시험판은 고정 SHA `10206483...` 소스이므로, **아무 변경 없이 재실행하면 C024 새 탭이 보이지 않는다.** C024 이후 코드는 기존 V2 설치본의 프로그램 파일만 검증된 무손실 업데이트 절차로 적용해야 한다. 이 업데이트/복원 스크립트가 검증·제공되기 전에는 사용자에게 직접 소스 파일을 덮어쓰라고 지시하지 않는다.
- 프로그램 업데이트 전에는 V2 프로세스 종료 여부/버전 SHA/대상 경로를 확인하고, 이전 실행 가능한 상태의 **롤백용 복구 사본**을 갖춘다. 임시 staging·롤백 백업이 기술적으로 필요하면 관리된 임시 파일로만 사용하고 별도의 사용자용 설치본/실험 프로젝트를 만들지 않는다. 검증 실패 시 기존 동작 버전을 보존하고 자동 삭제·강제 덮어쓰기 금지.
- **V1.0.2의 기존 설치본 `D:\03 자연풍경 비디오\NatureVideoStudio_V1_0_2`은 업데이트 대상이 아니다.** V1 데이터 `D:\NatureVideoStudio`, 복구 `D:\NVS_Recovery`, Windows Credential Manager 기존 키, V2 사용자 데이터 `D:\NatureVideoStudio_V2_Data`는 절대 덮어쓰기·초기화·삭제하지 않는다.
- 체크리스트 PASS를 **GitHub CI PASS**와 **사용자 PC 실사용 검증 상태(PASS/FAIL/NOT_TESTED)**로 따로 표시한다. 사용자가 아직 직접 확인하지 않았으면 "사용자 PC 미검증"이라고 기록하고 전체 GUI 동작을 입증한 것으로 표시하지 않는다.
- 실제 Windows 실사용 검사가 불필요한 비GUI 조사 문서는 GitHub 근거·CI로 점검하되, 화면/다운로드/재생/Windows 패키징 관련 항목은 기존 V2에서 직접 확인한다.
- 사용자 보고: 매 항목 `GitHub 코드 검증 → 기존 V2 설치본 같은 경로 업데이트 → 사용자가 실행 후 확인/오류 보고 → 오류 시 수정·같은 설치본 재검사 → 통과하면 다음 C번호`. **새 폴더 생성/새 체크리스트 추가를 기본 절차로 제안하지 않는다.**
