# C010 — V2 오류 후 V1.0.2 안전 복귀 UAT

**상태: 미완료 / 실제 V2 장애 후 복귀 시험 SKIP.** C010의 3/3점을 부여하려면 **실제로 실행 가능한 V2 시험판에서 오류를 관찰하고 종료한 다음**, V1.0.2의 GUI·DB·키·기존 사용자 영상이 유지되는 것을 확인해야 한다. 현재 V2 GUI/EXE가 없으므로 이를 흉내 낸 테스트를 실제 복귀 성공으로 표시하면 안 된다.

## 이미 확보된 증거

- C002 V1.0.2 원본 ZIP 및 C004 DB 백업은 각각 SHA256으로 검증 완료. 복구 디렉터리: `D:\NVS_Recovery`.
- C009에서 사용자가 실제 Windows PowerShell로 `before` → `after`를 실행한 결과: V1 프로그램 및 시작 스크립트 존재, 저장 경로 `D:\NatureVideoStudio`, SQLite SHA256 `4D2BDC3567A6FA7CFA1577DCB42D3A582551B5F972AA55057BEB0EA7654E7973` 변경 없음, Pexels/Pixabay 키 존재 상태 유지, C002/C004 백업 해시 MATCH.
- C005에서 기존 사용자 영상은 확인된 모든 저장 폴더에서 0개로 확정됨. 따라서 **실제 저장 영상 재생·파일 해시 복원 확인은 N/A**이며 성공으로 위조하지 않는다.
- C007에 의한 V2 프로그램 예정 폴더 `D:\NVS_V2_Trial_App`, V2 데이터 예정 폴더 `D:\NatureVideoStudio_V2_Data`는 설계만 존재한다. 실제 설치 여부 미검증.

## 위험 방지 원칙

- 원본 V1 폴더·SQLite·API 키·캐시·설정·사용자 영상·C002/C004 백업은 **덮어쓰기, 자동 복원, 삭제, 이동, 리셋 금지**.
- 테스트를 위해 실제 V1 DB를 고의로 손상시키거나 V2 DB를 삭제하지 않는다. V2 장애는 나중에 제공될 **모의 네트워크 타임아웃/미리보기 에러 등 격리된 실패 주입**으로 일으킨다.
- V2에서 오류가 발생하면 **V2만 정상 종료**한다. 강제 종료, 작업 관리자 프로세스 일괄 삭제, 드라이브 정리, 무조건적인 재설치는 하지 않는다.
- 복귀는 V1 기존 폴더의 프로그램을 그대로 실행하는 것. 자동 DB 역이관이나 Windows keyring 삭제를 수행하지 않는다.
- 해시를 확인하기 위해 V1 DB를 SQL 쓰기 모드로 열지 않는다. 로그에는 키 자체, HTTP Authorization, 키 접두사, DB 내부 원문을 출력하지 않는다.
- V1 화면에서 사용자 키 값이 그대로 보이면 스크린샷을 공유하기 전에 완전히 가린다.
- 기존 V1 미리보기 오류는 별도로 알려진 V1.0.2 결함이므로, 'V1로 돌아와 모든 미리보기가 정상'이라고 말할 근거가 아니다.

## 지금 가능한 읽기 전용 복귀 준비도 확인

이미 C009의 `%TEMP%\NVS_C009_windows.py`와 `%TEMP%\NVS_C009_V1_baseline.json`이 저장돼 있으므로, Windows에서 C010 스크립트를 검증된 SHA가 고정된 GitHub URL로 내려받아 한 번 실행한다.

```powershell
$c010 = "$env:TEMP\NVS_C010_rollback.py"
$url = "https://raw.githubusercontent.com/1976haru/newvideo/<PINNED_COMMIT>/tools/audit_c010_rollback.py"
Invoke-WebRequest -Uri $url -OutFile $c010 -UseBasicParsing
py -3 "$c010"
```

- 입력: 기존 C009 메타데이터 기준선, C009 감사 스크립트, 보안 저장소 마스킹 조회, 원본 DB SHA, 백업 SHA.
- 출력: `C010_V1_FALLBACK_READINESS_PASS_ONLY`이면 V1 보존 상태가 준비됐다는 의미일 뿐 V2 오류 후 복귀 PASS는 아니다.
- 도구는 모든 경우에 `V2_CRASH_INJECTED: False` / `V2_TO_V1_GUI_ROLLBACK_TEST: SKIP_NOT_RUN`을 출력한다.
- `C010_BLOCKED_...` 또는 `C010_REVIEW_...`이면 실제 프로그램/DB를 수정하지 말고 조사한다. 보안 저장소에 키가 없다고 단정하거나 재입력을 요구하지 않는다.
- 진단용 보안 저장소 조회에서는 존재 여부를 판별하기 위해 비밀값이 일시적으로 프로세스 메모리에 들어올 수 있으나 로그·파일로 반환되는 것은 PRESENT/ABSENT 등 상태뿐이다.

## 실제 V2 빌드 후 시행할 사용자 UAT (아직 미실행)

| 번호 | 순서 | PASS 기준 | 증빙 |
|---:|---|---|---|
| 1 | V1·V2 종료 상태에서 원본 ZIP·DB·백업·V1 설정 경로 기록 | SHA256/경로 비교 및 백업 존재, 키 마스킹 | C009/C010 출력 |
| 2 | V2 시험판을 **별도 설치 경로**에서 실행하고, 모의 네트워크 오류 등 안전한 실패를 확인 | V2 오류 원인이 명확히 표시되고 V1 파일에 손상이 없음 | V2 오류 화면 스크린샷(키 가림) |
| 3 | V2만 종료하고 기존 V1의 `START_NATURE_VIDEO_STUDIO.cmd` 실행 | V1 창 정상 등장, 비밀키 재입력 요구 없음 | V1 시작 화면 스크린샷 |
| 4 | V1 설정 화면에서 원래의 데이터 폴더와 API 키 존재/마스킹 상태 확인 | `D:\NatureVideoStudio`, Pexels/Pixabay 키 상태 그대로 | 개인정보 가린 설정 화면 |
| 5 | V1을 종료하고 진단으로 DB SHA와 백업을 다시 비교 | 원본 DB/백업 해시와 기존 API 키 존재 상태 MATCH | C009/C010 마스킹 로그 |
| 6 | 기존 사용자 영상 확인 | 이전 C005에서 0개이므로 **N/A**, 새로 다운로드하거나 가짜 파일 만들지 않음 | C005 기록 |
| 7 | V1 기본 동작에 대해 사용자가 GUI를 확인 | V1 실행과 최소한의 화면 탐색 가능. 기존 V1 미리보기 버그는 별도 문제로 기록 | 문제 없으면 GUI 캡처, 실패 시 오류 캡처 |

최종 PASS에는 **실제 V2 실패·V1 복귀 기록, 안전 경로/DB/키 검증, 화면 캡처**가 모두 있어야 한다. 파일·DB·키의 단순 존재만으로는 'V2 중단 후 복귀 정상'이 입증되지 않는다.

## 테스트 명령

`python -m pytest -q`
